# 台股投資決策輔助系統

雙擊桌面圖示 → 瀏覽器開啟儀表板 → 看今天有沒有要處理的事。

核心設計原則只有一句：**規則寫在系統裡，不寫在腦袋裡。**
系統負責計算與提醒，出場與否永遠由你人工確認。

---

## 第一次使用

**在 Finder 裡雙擊 `launch/安裝.command`**，然後照著畫面走。

它會裝套件、跑測試確認裝好了、把兩個捷徑放到桌面，
再問你要不要補歷史資料和開每日排程——每一步都會先問過你。

裝完桌面上會有兩個圖示：

| 捷徑 | 用途 |
| --- | --- |
| **投資儀表板** | 雙擊直接開網頁介面。**每天用這個。** |
| **投資工具箱** | 雙擊跳出選單：補歷史、跑回測、產生研究筆記、開關排程、檢查資料源 |

最後**在畫面上把範例持股換成你自己的**——
「持股異動 → 新增持股」填表送出即可，不需要編輯任何檔案。
範例持股（006208 / 2412 / 2330）請用「登記出場」移除或直接改掉。

<details><summary>不想用捷徑，想自己下指令</summary>

```bash
pip3 install -r requirements.txt
python3 src/history.py --months 24    # 補歷史（波段策略與研究筆記需要）
python3 webapp/app.py                 # 開儀表板
```

</details>

## 四個頁面

| 頁面 | 用途 |
| --- | --- |
| **今日** | 待辦訊號、投組總覽、持股明細、買進理由、觀察清單、決策紀錄 |
| **研究** | 每檔的價格分析、產業背景、該去查什麼、名詞辭典 |
| **歷史** | 過去的決策紀錄與每日報告存檔、覆盤時該問的四個問題 |
| **規則設定** | 停損停利 %、停損基準、我的目標、規則變更紀錄 |

儀表板由上往下的順序是刻意排的：**今日待辦**在最上面，沒事時它會直接說「今天不需要動作」。

但每天真正該花時間看的是**「當初的買進理由」**那一段——問自己一句：理由現在還成立嗎？
停損線防的是「虧太多」，那一段防的是「抱著一個已經錯掉的理由」。

## 研究筆記

儀表板的「研究」分頁，或 `python3 src/research.py`。

用來回答「我到底買了什麼、現在在發生什麼」——
跟「今日」那頁的「今天要不要動作」是兩種完全不同的閱讀節奏，所以分開。

### 報告分成三塊，而且標示得很清楚

| 區塊 | 是什麼 | 可信度 |
| --- | --- | --- |
| **價格在說什麼** | 從日 K 直接算的：各期間報酬、一年區間位置、起漲點、量能、波動度、相對大盤、同業比較 | 可自行驗證 |
| **這家公司在做什麼** | 產業、供應鏈位置、營收跟著什麼跑、該追蹤什麼、這個產業最常見的誤判 | 人工整理，**會過時** |
| **要你自己去查** | 系統沒有資料源的部分，附上該問什麼問題 | 系統不知道 |

### 它不能做什麼（重要）

**它不能告訴你「為什麼」漲。**

價格會動是因為新聞、財報、法說會、法人買賣、總體經濟——
這套系統**一個都沒接**。它只能告訴你**漲勢的形狀**：
漲了多久、漲幅多少、量能有沒有配合、
是整個產業一起漲還是它自己獨走、現在的價格在過去一年的什麼位置。

形狀本身就很有用。舉例來說，報告會這樣寫：

> 同業近 3 個月：南電 +25%、金像電 +2%（平均 +13%），它自己 +32%
> —— **它明顯走得比同業強**。同一個產業裡只有它大漲，
> 通常代表市場在反映這家公司自己的事（訂單、財報、題材），
> 而不是整個產業的景氣——那就更需要去查清楚那件事是什麼。

它把「該去查什麼」變得具體，但查還是要你自己查。

### 名詞辭典

不熟 PCB、封裝、CoWoS、ABF 載板、本益比、除權息這些詞？辭典有 40 條，
每一條都是「一句話講完 + 多一點背景 + 為什麼你會在新聞裡看到它」。

研究頁下方可以直接搜尋，或用命令列：

```bash
python3 src/research.py --term CoWoS
python3 src/research.py --term 載板      # 別名也查得到（ABF → IC 載板）
python3 src/research.py --glossary       # 印出全部
```

每檔股票的報告下方也會自動附上它相關的名詞。

### 知識庫在哪、怎麼改

```
config/glossary.yaml   名詞辭典（40 條）
config/sectors.yaml    產業地圖（26 檔）
```

兩份都是人工維護的純文字檔，看得懂就改得動。
買了新標的就照格式加一筆，找不到的代號不會出錯——報告照樣產生，只是少了背景那一段。

這兩份檔案**刻意只寫變化很慢的東西**（商業模式、供應鏈位置、該看什麼指標），
不寫市占率、客戶名單、目標價、財測。那些寫下來三個月就過期，
而過期的資料比沒有資料更危險，因為你會以為它還準。

## 模擬倉（paper trading）

除了監控你手上的持股，系統還可以**自己跑一套 1～2 週的波段策略**——
產生進出場決策、算進交易成本、記錄每一筆，然後在日報裡跟你報告。

**全程是虛擬的。沒有連接任何券商，不會送出任何真實委託。**
目的是先累積幾個月「這套規則實際上會做什麼決定」的證據，再決定要不要用真錢。

### 開始跑

**1. 補歷史日 K**（策略要算均線，需要至少 61 根 K）

```bash
python3 src/history.py --months 24
```

預設補「持股 + 觀察清單」裡的所有代號。

**只會抓缺的月份**——過去的日 K 不會再變，已經有的直接跳過，
所以第一次大約三分鐘，之後每次只補最近兩個月，幾秒就好。
每抓完一個月就存檔，中途 Ctrl+C 不會弄丟已經抓到的部分，重跑會從缺的地方接下去。

```bash
python3 src/history.py --status     # 看目前累積到哪
python3 src/history.py --force      # 連已有的月份也重抓
INVEST_FETCH_DELAY=0.8 python3 src/history.py   # 調快（預設 1.5 秒／次）
```

> 間隔調太低會被端點擋，被擋了反而更慢，不建議低於 1 秒。

**2. 先回測，看這組參數在過去會做什麼**

```bash
python3 src/backtest.py
python3 src/backtest.py --verbose      # 印出每一筆成交
```

**3. 之後每天跑 `src/main.py` 時模擬倉會自動前進一天。**

在 `config/paper.yaml` 把 `enabled` 改成 `false` 就完全關掉，
或單次跳過：`python3 src/main.py --no-paper`。

### 策略在做什麼

進場要**四個條件同時成立**（收盤時判斷，隔日開盤成交）：

| 條件 | 為什麼 |
| --- | --- |
| 收盤站上 60 日均線 | 不逆勢接刀 |
| 收盤站上 20 日均線 | 中期動能還在 |
| 突破前 20 日最高價 | 這就是進場觸發 |
| 近 20 日均量 ≥ 500 張 | 買得到、賣得掉 |

出場四選一，**停損優先**：停損 −8%、停利 +15%、移動停損（預設關閉）、
或抱滿 15 根 K 還沒觸發就時間出場。最後這條是「波段」的定義——
沒有它，一檔不上不下的股票會變成你根本沒打算做的長期投資。

### 停損寬度：固定 % 還是跟著波動度走

`config/paper.yaml` 的 `stop_mode` 有兩個選擇：

| 模式 | 停損怎麼算 | 適合 |
| --- | --- | --- |
| `pct`（預設） | 固定 −8%，每檔一視同仁 | 波動度接近的一組標的 |
| `atr` | 進場價 − 2 × ATR(14) | 波動度差很多的一組標的 |

**ATR（平均真實區間）就是「這檔一天通常會動多少錢」**，單位是元不是百分比，
而且會把跳空算進去——一根開盤就跳空的 K，只看高低差會低估它的波動。

為什麼會想換：固定 8% 對每檔都一樣，但一檔日常波動 1% 的電信股
和一檔波動 10% 的航運股，8% 的意義完全不同。研究筆記會直接幫你換算：

> ATR(14) **7.18 元**（現價的 10.1%，也就是「一天通常會動這麼多」）——
> **這檔的 8% 停損太緊**，只有 0.8 倍日常波動，很容易被雜訊掃出場。

> ATR(14) **0.94 元**（現價的 1.0%）——8% 停損等於 8.3 倍日常波動，**偏寬**，
> 真的觸發時已經賠了不少。

停損寬度在**進場當下就固定**，之後不會隨 ATR 變動——
會移動的停損線沒辦法讓你在進場前算出這筆最多會賠多少。
每筆成交紀錄都會寫下當時用的基準（`2×ATR(14)＝10.00 元`），覆盤時看得出來。

設成 `atr` 但進場時歷史不足以算 ATR 的話，會退回固定百分比，
**並在紀錄裡註明**——安靜地換一套規則是最糟的做法。

### 三個刻意保守的設定

1. **成交價用隔日開盤價**，不是當日收盤價。收盤價是你做決定當下才知道的數字，
   拿它下單等於偷看未來，回測會漂亮得不像話。
2. **交易成本照實算**：手續費 0.1425%（可設折扣、最低 20 元）買賣各一次，
   賣出再課 0.3% 證交稅。來回大約 **0.47%**。停利設 15% 而不是 3%，
   一部分原因就在這裡。
3. **只買整張**。零股的成本結構和流動性不一樣，不混在一起模擬。

### 日報會告訴你什麼

- 今天成交了什麼、成交價多少、手續費和稅各多少
- 明天開盤要下什麼單、理由是什麼
- **其他標的今天為什麼沒買** —— 是趨勢不對、沒突破、量太小、
  名額滿了，還是資金不夠。這段最容易被省略，但它才是你之後調參數的依據。

### 產出

```
data/history/          歷史日 K（衍生資料，不進版控，隨時可重建）
data/paper_state.json  當前虛擬現金、持股、待執行委託
data/paper_trades.jsonl 每一筆成交，含完整的進出場理由  ← append-only
data/paper_equity.jsonl 每日淨值曲線                    ← append-only
```

`paper_trades.jsonl` 每一筆都記著當初進場時四個條件各是什麼數字。
兩個月後你不會只看到「買了 2330」，而是看到「當時它站上 60 日均線 116.94、
突破前 20 日高點 133.90」——那才有辦法判斷規則本身對不對。

### ⚠️ 讀績效數字之前

- **少於 30～50 筆交易的統計沒有意義。** 勝率 70% 但只有 6 筆，那是雜訊。
  報告和回測都會在樣本不足時主動提醒你。
- **不要看到虧損就調鬆停損、看到獲利就調緊停利。** 那是最常見的自我欺騙路徑，
  你會得到一組在歷史上很漂亮、對未來毫無預測力的參數。
  要改就在 `config/paper.yaml` 的 changelog 留一行。
- 回測**沒有**模擬「買不到」的情況，假設你要的張數在開盤都成交得掉。
  對日均量 500 張以上、每次只買 20% 部位的規模還算合理，資金放大後會失真。

## 訊號說明

| 訊號 | 意義 |
| --- | --- |
| 🔴 觸發停損 | 收盤 ≤ 停損線，規則判定該出場 |
| 🟢 觸發停利 | 收盤 ≥ 停利線，規則判定該出場 |
| 🟠 接近停損 | 距停損線 3% 以內（預警） |
| 🔵 接近停利 | 距停利線 3% 以內（預警） |
| ⚪ 續抱 | 在區間內 |
| ⚓ 核心部位 | 不套用停損停利（長期持有的 ETF 等） |
| ❔ 無行情 | 當日查無報價（停牌、代號錯誤） |

「距停損」／「距停利」= **現價要再變動多少 % 才會碰到那條線**。
距停損 `−14%` 代表還要再跌 14% 才停損；轉為正數代表已經跌破。

### 停損基準

- **以成本價計算**（預設）：成本 100、停損 10% → 停損線固定在 90。
- **以進場後最高價計算**（移動停損）：成本 100、最高漲到 150 → 停損線變成 135，鎖住部分獲利。

移動停損的歷史高點來自每日紀錄，剛啟用的前幾天會退化成用成本價計算，儀表板會標註。

## 檔案在哪

```
config/positions.yaml   持股（介面會自動維護，也可手動編輯）
config/strategy.yaml    停損停利規則 + 變更紀錄
config/paper.yaml       模擬倉：資金、成本、波段策略參數
config/glossary.yaml    名詞辭典（研究筆記用）
config/sectors.yaml     產業地圖（研究筆記用）
config/mail.yaml        Email 設定（你自己建立，不進版控）

data/reports/           每日報告存檔
data/signals.jsonl      append-only 訊號紀錄  ← 覆盤的證據
data/journal.jsonl      決策紀錄
data/backups/           每次修改設定前的自動備份（保留最近 50 份）
```

### `signals.jsonl` 是最重要的產出

每天一行，記錄當天的**規則參數**、價格、停損停利線、訊號判定。
因為它記錄了「當天用的是什麼參數」，兩個月後你可以驗證自己有沒有在過程中偷偷調鬆停損。
沒有這份紀錄，你會拿到一份回頭看很合理、但什麼都證明不了的資料。

**不要回頭編輯它。** 需要修正就 append 新的一行。

## 測試

```bash
python3 tests/test_signals.py     # 停損停利判斷的 13 條分支
python3 tests/test_store.py       # 透過介面改設定不會弄壞 YAML
python3 tests/test_paper.py       # 交易成本、進出場訊號、成交、名額上限
python3 tests/test_history.py     # 日 K 存取、民國日期、TWSE 解析
python3 tests/test_backtest.py    # 回測引擎的不變式（合成資料，不連網）
python3 tests/test_research.py    # 指標計算、ATR、名詞查詢、知識庫完整性
```

全部不需要 pytest，也不連外網，跑完會印 `全部通過 ✅` 或以非零狀態結束。

**改了 `src/` 底下任何檔案之後請先跑過**——
規則被改壞是沉默的：報告照樣產生、數字照樣漂亮，只是錯的。

`test_backtest.py` 檢查的不是「策略賺不賺錢」（合成資料證明不了那件事），
而是**引擎有沒有作弊**：現金會不會變負的、部位有沒有超過上限、
淨值等式對不對、成交價是不是真的來自隔日開盤。
只要有一條不變式被破壞，後面所有績效數字都不用看了。

`test_research.py` 除了驗算指標，還會把 `sectors.yaml` 引用的名詞
跟 `glossary.yaml` 交叉比對一遍。你之後加標的時打錯一個字，
報告不會壞掉——它只會安靜地少一段，這支測試就是為了讓錯字當場被抓出來。

## 資料源

| 市場 | 端點 | 費用 |
| --- | --- | --- |
| 上市 | `openapi.twse.com.tw/v1/exchangeReport/STOCK_DAY_ALL` | 免費、免金鑰 |
| 上櫃 | `tpex.org.tw/openapi/v1/tpex_mainboard_daily_close_quotes` | 免費、免金鑰 |

兩支都是「一次回傳全市場」，追蹤 3 檔或 300 檔都只打兩次 request。內建 3 次重試與 30 分鐘快取。

歷史日 K 另外走「逐檔月報表」端點（`src/history.py`），
上市與上櫃都支援，`--market auto` 會自己判斷該打哪一支。
這兩支是網頁後端 API 而非正式開放資料，改版風險比較高，
所以解析一律用**欄位名稱比對**而不是寫死索引，而且忽略名稱裡的空白——

> 上櫃回傳的日期欄位實際上叫「**日 期**」，中間有一個空格，
> 同一份回應裡其他欄位卻沒有。用子字串比對會找不到它，
> 然後整個月靜靜地變成零根 K：不拋例外、沒有錯誤訊息，只是均線少一段。
> `tests/test_history.py` 用兩個市場的實際欄位做迴歸測試，就是為了這個。

還有自我檢查：

```bash
python3 src/history.py --self-test
```

它會對兩個市場各抓一次、印出實際回傳的欄位，解析不出來時直接告訴你。
（工具箱選單裡的「🩺 檢查資料源是否正常」就是跑這個。）

⚠️ 這是**收盤後**的資料，不是即時報價。系統定位是盤後決策，不是當沖。
