# 操作手冊

從第一次設定，到兩個月後覆盤，全部的操作都在這裡。

---

## 0. 第一次設定（只做一次，約 15 分鐘）

### 安裝

```bash
pip install -r requirements.txt
```

### 換掉範例持股

打開 `config/positions.yaml`，把裡面的三筆範例**全部刪掉**，換成你自己的。
每一筆長這樣：

```yaml
  - code: "2412"
    shares: 3000
    cost: 132.0
    entry_date: "2026-05-08"
    thesis: "現金流部位：電信股現金殖利率穩定，波動低。"
    invalidate: "配息政策轉差，或本業營收連兩季衰退。"
```

三個容易踩的地方：

| 欄位 | 注意 |
| --- | --- |
| `code` | **一定要加引號**。`006208` 沒引號會被 YAML 讀成數字 `6208`，然後查無行情。 |
| `shares` | 是**股數**不是張數。1 張 = 1000 股。 |
| `cost` | 每股成本。把手續費攤進去會更準（成本 ×1.001425）。 |

### 設定你的目標

打開 `config/strategy.yaml`，改最上面的 `objective`。這行不影響計算，但每天都會印在報告最上面。

寫成**可量測**的一句話，不要寫「賺錢」：

```yaml
objective: >-
  未來 12 個月產生 NT$X 可支配現金，且整體最大回撤不超過 15%。
```

有了這行，之後你想換標的時才有東西可以對照——不然你不知道自己在最佳化什麼。

### 確認跑得起來

```bash
python3 src/main.py
```

看到報告印出來、`data/reports/` 出現當天的 `.md` 就成功了。

## 1. 每天的例行動作（3 分鐘）

台股 13:30 收盤，資料源大約 **14:00–15:00** 更新當日行情。太早跑會拿到前一天的資料（報告最上面會標註行情日期距今幾天）。

```bash
python3 src/main.py
```

報告由上往下看，順序是刻意設計的：

**① 今日待辦** — 只有這一段需要你做決定。
沒有觸發訊號時它會直接說「今日不需動作」，你就可以往下滑了。

**② 投組總覽** — 掃一眼總損益。

**③ 持股明細** — 看「距停損」還剩多少緩衝。

**④ 當初的買進理由** — **這段才是每天真正該花時間看的**。
對每一檔問自己一句：**當初的理由現在還成立嗎？**

- 理由不成立了 → 就算沒到停損線也該考慮出場
- 理由還成立 → 就算帳面虧損也不必恐慌

停損線防的是「虧太多」，這一段防的是「抱著一個已經錯掉的理由」。兩件事不一樣。

**⑤ 決策紀錄** — 在報告檔案底部寫一行。今天沒動作就寫「無動作」。

> **如果你決定不照系統訊號執行，一定要寫下理由。**
> 這是整個模擬期最重要的資料——不是為了記帳，是為了讓你兩個月後能回頭看：
> 你覆蓋系統判斷的那幾次，事後證明是對的還是錯的。

## 2. 進場時

**在按下買進之前**，先把 `thesis` 和 `invalidate` 寫好。

順序很重要。買完再補寫的理由，一定會被你已經買了這件事影響。

```yaml
  - code: "2308"
    shares: 1000
    cost: 850.0
    entry_date: "2026-07-29"
    thesis: "（一句話：我為什麼買）"
    invalidate: "（一句話：什麼情況代表我錯了）"
```

`invalidate` 最難寫也最有價值。它不能是「股價跌」——那是停損線的工作。
它要寫**基本面層次**的失效條件：訂單、毛利率、配息政策、競爭格局。

長期持有不想被停損打擾的部位（例如市值型 ETF），加一行：

```yaml
    core: true
```

---

## 3. 出場時

**不要刪掉那一筆。** 加兩個欄位：

```yaml
    exit_date: "2026-08-15"
    exit_price: 920.0
```

程式會自動把它排除在報告之外，但紀錄留著。

> ⚠️ 目前的限制：已出場的部位只是從報告消失，**已實現損益不會呈現在任何地方**。
> 資料還在 `data/signals.jsonl` 裡撈得回來，但報告看不到。

## 4. 改規則時

改 `config/strategy.yaml`。改完務必做兩件事：

**① 在 changelog 加一行**

```yaml
changelog:
  - date: "2026-07-29"
    note: "初版建立：10% 停損 / 22% 停利，以成本價為基準。"
  - date: "2026-09-01"
    note: "停損放寬到 12%，因為 8 月被雜訊掃出場兩次。"
```

**② 跑測試**

```bash
python3 tests/test_signals.py
```

改壞判斷邏輯是沉默的——報告照樣產生，數字照樣漂亮，只是錯的。測試是唯一擋著這件事的東西。

### 什麼時候該改規則、什麼時候不該

| 情境 | 該不該改 |
| --- | --- |
| 「被停損掃出場兩次，之後都漲回來」 | 可以考慮，但要等樣本夠多，而且要寫進 changelog |
| 「這次快到停損了，先放寬一下」 | **這就是系統要防的事** |

第二種情況如果發生了，**不要偷偷改**——照改，但在 changelog 誠實寫下當時的理由。
兩個月後你看到那行字，會學到比任何回測都多的東西。

## 5. 模擬盤怎麼跑

系統不區分真倉和模擬倉，操作**完全一樣**——照樣填 `positions.yaml`、照樣每天跑、照樣寫決策紀錄，只是不真的下單。

模擬期要測的是兩件事，第二件比第一件重要得多：

1. **系統穩不穩**：數字對不對、有沒有漏抓、假日會不會出錯。
2. **你自己能不能照著執行**：訊號叫你停損時，你有沒有找理由不停？

第二件事只有**每天誠實寫決策紀錄**才測得出來。跳過那一步，兩個月就只測到第一件事。

建議做法：
- 開一個獨立資料夾跑模擬倉，跟真倉分開（複製整個專案就行）
- 或先只跑模擬倉，兩個月後再開真倉

## 6. 兩個月後怎麼覆盤

`data/signals.jsonl` 是唯一的證據。每行是一天，記錄當天用的**規則參數**和每檔的訊號。

先跑這個——它會告訴你規則有沒有被改過：

```bash
python3 -c "import json;seen=set()
for l in open('data/signals.jsonl'):
    r=json.loads(l);k=json.dumps(r['rules'],sort_keys=True)
    if k not in seen: seen.add(k); print(r['trade_date'], k)"
```

只印出一行 = 你整個模擬期沒動過規則。印出多行 = 每一行都是一次規則變更，去對照 `strategy.yaml` 的 changelog 看當時為什麼改。

然後問自己四個問題，按重要性排序：

**① 系統發出的訊號，我實際執行了幾次？**
執行率遠低於 100% 的話，問題不在系統，在紀律。這是模擬期最該發現的事。

**② 我覆蓋系統判斷的那幾次，事後對還是錯？**
去讀報告底部的決策紀錄。如果覆蓋通常是錯的 → 以後別覆蓋。如果通常是對的 → 你的直覺裡有系統沒捕捉到的東西，把它變成規則。

**③ 停損被觸發的那幾檔，之後漲回去了嗎？**
常常漲回去 = 停損太緊（被波動掃出場），考慮放寬或改用 ATR 模式。

**④ 當初的 thesis，回頭看有幾個是對的？**
這是判斷品質的直接檢驗。表現好但理由是錯的 → 那次是運氣，別把它當成方法。

## 7. 常見狀況

| 狀況 | 原因 / 處理 |
| --- | --- |
| 報告顯示「行情日期距今 N 天」 | 假日或資料源未更新。N ≥ 3 且非連假才需要檢查。 |
| 某檔顯示「❔ 無行情」 | 九成是 `code` 沒加引號，或代號打錯。停牌也會這樣。 |
| 想看報告但不想寫檔 | `python3 src/main.py --dry-run` |
| 給 cron 用，不要印出來 | `python3 src/main.py --quiet` |
| 同一天重跑 | 報告會覆蓋，`signals.jsonl` 會多 append 一行（用 `generated_at` 可以分辨）。不影響計算。 |
| `ModuleNotFoundError: yaml` | `pip install -r requirements.txt` |

## 8. 什麼時候才該接下一步

**不要現在就接 Email 和排程。** 建議的順序：

1. **手動跑 1–2 週** ← 你在這裡
   確認數字對、報告順手、有沒有想改的欄位。這階段改東西成本最低。
2. **接排程**（cron 或 GitHub Actions），還是自己開檔案看
3. **接 Email**，管線完全穩定之後
4. **Phase 2 的 LLM 分析**，最後才做

反過來做的話，你會很快擁有一個每天準時寄信、但損益算錯的系統——而且因為信每天都來，你會更晚才發現。
